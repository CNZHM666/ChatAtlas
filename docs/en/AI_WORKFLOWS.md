# ChatAtlas AI workflows and validation limits

The current document workspace only organizes and maintains prose. Independent project Q&A, matters and evolution analysis are retired; `generateFocusUpdate` returns after chapter merging, directory organization and source freshness checks without a project-state tail. References to those modules below describe legacy compatibility and regression coverage.

[简体中文](../../AI_WORKFLOWS.md) · **English**

File import accepts official exports from ChatGPT, Claude, Gemini (Google Takeout JSON) and DeepSeek, plus Markdown/JSON transcripts from other AIs. Beta website adapters for Claude, Gemini, DeepSeek, Doubao, Kimi and Qianwen (including Qwen international) run automatically after browser website permission, with pause/resume controls. They support the native sidebar, local search, project association, loaded-message sync, source location and composer insertion. Website history import reads loaded titles and saves loaded bodies one at a time; it saves currently loaded messages, not guaranteed full history. ChatGPT retains its dedicated history inventory and body sync. The new adapters still need signed-in live-site acceptance; BYOK model providers are independent of conversation-source support.

## Which actions invoke a model

| Action | Default behavior |
| --- | --- |
| Reading, keyword search, original navigation, existing projects and saved contexts | Local, no model call |
| Project file export | Local export of saved overview, selected Wiki chapters and optional matters; no model call |
| Initial organization or source updates | BYOK within confirmed scope, reusing valid analysis |
| Legacy project questions/evolution | Retained data and compatibility code; no current workspace entry |
| Semantic enhancement and embedding index | Optional advanced operations that may send relevant material |
| Connection test | Explicit request, potentially billable |

## Organization pipeline

1. Check confirmed scope, content signatures and reusable analysis. Budget the initial read into batches.
2. Start complete catalogue windows from the contiguous finished reading prefix while later reading continues. Reading and directory work share one provider allowance, capped at three. Preserve window boundaries, source order and request caches; do not create smaller paid windows merely to start earlier. Small catalogues still use one request after reading. From its first round, global reconciliation targets at most seven parents (strictly fewer than eight) and regroups both parents and related child questions; shared materials travel together, with complete original support mapped locally to the final scopes. Input windows, convergence and recovery remain bounded. The UI keeps this work under “Read and organize sources”, without a false completed percentage during final ownership checks.
3. Write from assigned chapters and subtopics. Remove exact duplicate notes; similar passages with different conditions/sources remain distinct.
4. Validate citations, ownership, body and subtopic coverage. Reuse successful batches instead of rereading history after another batch fails.
5. Preview and save explicitly. Personal edits are not overwritten, and a complete evolution analysis is not automatically appended to initial Wiki generation.

The implementation sequences source reading, writing preparation and composition, with a separate direct path for short discussions. The catalogue establishes material identity; after scope filtering and fact projection, writing refreshes evidence only inside existing materials without adding IDs. Directory requests and saved inclusion/exclusion keys remain compatible, as do existing preparation and writing checkpoints. Writing materials require chapter ownership in their types, with runtime preflight retained; recovery reservations share one policy.

Cross-AI organization: when the selected sources span two or more platforms, reading and writing materials carry their platform, and the model attributes AI suggestions to it. One AI's answer never confirms or replaces another's; only the user's own message records a choice. Before organizing, user questions are compared locally across platforms to find the same question answered by different AIs (no model call). Writing covers such a question once as a comparison: the shared conclusion, each AI's distinct suggestion and conditions, and the evidenced user choice or that none is recorded. After directory planning, a question's materials from different AIs are moved locally into the chapter and subtopic already holding most of them, removing any chapter or subtopic left empty; materials change placement only, never content or count, and an adjustment that would break the outline keeps the planner's outline. When writing is partitioned, the group goes into one request whenever the combined request fits the input budget. Single-platform scopes send unchanged requests and keep their caches. Matching uses text similarity, so heavily reworded questions may not be detected.

Missing chapters, invalid sources or incomplete writing recover only the affected material. Writing recovery allows min(32, max(6, twice the writing batch count)) extra requests and 48,000 reserved output tokens across the stage. Each logical batch shares four attempts/24,000 reserved output tokens across children, with split depth two and no nested format retries. Small missing-topic completions use a lower output ceiling unless code-rich evidence requires the normal limit. Learned splits expand at execution with the original logical batch context, preserving successful child cache identities on resume. Metadata repair has separate bounds. Interrupted final writing has at most one local retry, not a blanket policy for timeout, refusal or reasoning-only output. Directory truncation/convergence have separate bounded recovery. Keep completed work without publishing a false complete result.

Per-response limits of twelve claims and 12,000 body characters do not apply to an accumulated chapter. Writing checkpoints retain individually validated fragments; resume revalidates each fragment's format, sources and ownership, then merges locally and checks combined subtopic coverage. Never truncate claims or re-submit a locally merged article as a single model response. Fragment count is bounded by assigned subtopics and new fragments must reduce missing scopes. Legacy checkpoints and successful request identities remain reusable. An exact assigned subtopic returned as a section title can restore its omitted body heading when its citations support that scope; similar titles, conflicting headings, unknown sources and absent content cannot. Genuine claim-format failures receive specific field requirements within existing bounded recovery.

Concurrent failure reports retain only the originating batch context; draining siblings cannot append more batch labels to the same error. Completed requests remain retained. Analysis snapshots the pipeline ledger so later updates cannot disagree with already calculated attempt counts.

Small writing requests remain combined. Long chapters run in parallel, with dependent chunks sequential within each owner. Later chunks can receive at most eight whole paragraphs/1,800 characters of earlier explanations as navigation, never evidence. Verbatim reuse requires current support for the same meaning, status and conditions. Optional context is removed whole when it does not fit; source evidence is retained.

The first writing chunk returns a short chapterOverview in its existing response; normalization places it before the first ## heading in the saved body. Later chunks omit it. Legacy and explicit rewrite openings remain ordinary leading prose. Missing openings produce editorial feedback, never an excerpt fallback or an automatic extra summary call.

When a source-validated draft omits scopes, retain its prose and complete only missing topics with their whole supporting materials, up to three topics per request. Narrow topic count before fitting remaining allowance. Retain partially completed supplements only when the missing count strictly decreases. A single prose topic may use sufficient remaining output allowance; code, multiple topics and insufficient room retain their safe cap. The 48,000/24,000-token and four-attempt bounds remain unchanged. Genuine exhaustion appears as a writing pause, with technical quota details under diagnostics.

Chapter coalescing merges exact blocks within their full heading paths, preserving distinct parents, phases and proposal states. Repeated child headings no longer leave new text under the wrong sibling. Global overview selection excludes chapter-relative editorial introductions while retaining their source chapter and claims.

Fresh composition and explicit chapter rewrites share Reader edition v4 within the existing writing request: organize by chapter questions, then check repetition, version scope and adoption. Do not rebuild note outlines or infer adoption from recency/repetition. Prior-explanation navigation retains parent paths. Rewrite navigation includes unresolved scoped records with separate adoption and delivery metadata; navigation is never original proof. Composition checkpoints pin the writing edition. Pre-upgrade tasks retain their policy, partition budgets and explanation shape so successful requests remain reusable; the new policy applies to fresh tasks and explicit rewrites without clearing reading caches.

Reading and export share a compact layout projection: a level-three leaf under a level-two parent with one or two prose paragraphs (at most 420 Markdown characters in total) becomes a bold label. Wording, order and conditions remain. Substantial branches, longer explanations, code, tables, lists, quotes and recognized original headings remain; personal articles are exempt. Saved prose and claim bindings are unchanged. This layout is not semantic reconciliation.

## Language and content depth

Chinese output allows short technical labels but still checks English prose and long English sentences containing a few Chinese characters. Failure diagnostics retain field paths, not model bodies. On an actual BYOK language failure, one translation repair sends only invalid prose fields. Correct output, originals, quotes and project facts remain local. The patch is limited to 24 fields and 24,000 characters; validate paths, duplicates, literal code/quotes, sources and ownership afterward. Otherwise retain completed batches for explicit retry rather than resending all sources.

Directory planning receives bounded note summaries and fact subjects, not an original-message dump; writing retains the full detail inventory. Prompts favor concrete explanations and two heading levels, without minimum-word-count filler. Final writing ceilings scale with subtopics: fast up to 6,000, balanced 8,500 and deep 10,000 output tokens. Actual usage is provider-reported; legacy reading requests retain their budgets.

Local quality hints flag very short sections relative to rich material, apparent passed-result tables, and complete chapters missing an opening or containing repeated headings/paragraphs or batch commentary. Both chapter review surfaces show these hints; personal edits and stale signatures suppress them. Hints do not prove error, rewrite content or start a paid request. New prose distinguishes acceptance criteria, plans, reports and actual verification; chronology alone does not prove adoption. Chapter rewriting uses the same requirements, returns a candidate and makes at most one request per explicit action, with a 3,600–6,000 output ceiling based on subtopics. Oversized original material is reported, never silently cut.

Hints also identify dense deep outlines, possible empty citations and processing commentary such as “this batch mainly focuses”. Empty brackets are not globally deleted: only outer wrappers emptied by removal of a recognized wire citation are cleaned. Existing `[]`, arrays, links and code remain for review.

Overview and prose reuse saved facts through `project-knowledge-facts.ts` and `project-knowledge-view.ts`; `project-snapshot.ts` selects overview material. Natural paragraphs cover purpose, choices, constraints and supported status. Supplement/narrow/replace/coexist/conflict links need original evidence, matching scope and chronology. Adoption and delivery remain separate. Bound prose formulations retain detail and shared qualification, while quotes, code and personal edits stay intact. Unsupported replacements do not automatically apply. These local views add no model calls or fact store. `firstPreviewMs` measures the first usable preview in the run, not provider time-to-first-token.

## Matters and presentation

Open matters and ordinary records are separate. Constraints, assistant advice and unconfirmed descriptions do not automatically become unresolved decisions. **Add from discussions** reuses reading facts and reviews the original order, later choices, withdrawals and scope. Incremental checks retain old questions and separate answer proof, sending only bounded source windows. Missing short answers may add at most two adjacent user messages, each up to 3,600 characters, to the existing synthesis. A fully checked batch with no issues can be reused. Presentation changes do not invalidate reading caches or completed batches.

A resolution needs a locatable user choice, withdrawal or report. Role, quote, scope and chronology pass local checks and the existing verifier. Unrelated completion reports and another version's choices cannot close a question. Advice, plans, silence and unknown order are insufficient. Keep uncertainty open. Adopt selected new matters or add a result to an old one; personal edits and reopening take priority. Source changes cannot silently renew an old resolution's validity. Similar records across categories are suggested links, never automatic merges.

Wiki planning has no fixed minimum chapter count. Planning and rewriting favor one concrete subject; incremental updates may improve generated titles while retaining ownership IDs and personal titles. There is no global conjunction-stripping rule. Read-only Markdown presentation hides internal reference/uniform status columns and qualifies proposals naturally. Isolated calls become inline and narrowly recognized text diagrams simplify; real code, business statuses, originals and personal edits survive. New output avoids internal IDs, mechanical enumeration and subjective scores.

## Project export

The project toolbar opens the existing overview/Wiki file exporter. Separate project-context, sidebar-context and AI-refinement entries are retired. Historical data and compatibility helpers remain. Export makes no model call and does not regenerate knowledge or clear collections.

## Tokens, reuse and real quality

Initial complete analysis reads original material and also uses prompts, intermediate notes/plans, final output and possibly bounded recovery. Total tokens can exceed raw source input. Do not add character counts, conservative estimates and provider-reported tokens or infer a compression rate from mixed units.

A cache hit means local reuse for that step, not a new request there. Different inputs, scope, model or phase may miss. Missing usage/cost is unknown, not free. Usage distinguishes requests, reuse, failures, recovery and input/output.

Provider prompt caching is separate from that local reuse: the model still receives and processes the complete request, while an identical fixed prefix may be billed at the provider's cache rate and start faster. Every request places fixed instructions before per-batch text, so model-visible text, local request identities and successful caches are unchanged. OpenAI-compatible services (DeepSeek, Kimi, Qwen and others) and Gemini cache automatically under their own rules; the first-party Anthropic API marks a prefix only after it was sent recently, so one-off requests never pay for a cache write; the first-party OpenAI API receives a routing key. Third-party compatible gateways receive no vendor-specific cache fields. Provider-reported cached input tokens are recorded separately and remain included in input totals; when unreported they are unknown.

Wiki writing batches are calibrated by provider-reported tokens: each model records actual input divided by the local estimate, and after at least three valid reports writing batches use it (10% headroom, at most halving the estimate, never raising it). Implausible reports such as fixed placeholder values are ignored. The scale is frozen when writing starts and saved with the checkpoint, so a resumed run rebuilds the same batches and reuses completed requests; reading batches are not calibrated and existing reading caches stay valid. Before sending, each writing request is checked locally for its chapter roster, material ownership and subtopic citations; a request that cannot succeed is not sent and counts as a pre-send block. The organization CSV adds cached input tokens, the estimate-to-actual input ratio (overall and by stage), pre-send blocks and the writing scale.

Model roles: settings offer a main model and an economy model side by side. Reading originals uses the economy model; directory planning and Wiki writing use the main model; other light tasks keep their existing assignment. A batch the main model already read and cached is reused instead of being read again by the economy model; without an economy model everything uses the main model. Concurrency starts at 3 and, after consecutive successes, rises to 6 for first-party and large hosted APIs (OpenAI, Anthropic, Gemini, DeepSeek, Qwen, Kimi, Zhipu, SiliconFlow, Volcano Ark, OpenRouter, MiniMax); custom gateways stay at 3. A 429 halves it immediately and holds one request for a minute. The organization CSV adds the models used in each stage (models_by_stage).

Developer tests offer local regression, read-only saved-knowledge checks and a folded searchable manual plan. They preserve old records, make no model calls and do not modify projects. Cross-domain fictional cases exercise adoption, supplements, replacements, credentials, unrelated resolutions and prose consistency.

Automated mocked-provider tests establish program behavior, not long-conversation completeness, latency or truth. Use authored/redacted material you are willing to send and record model, time, cost, omissions and handoff performance using the [release checklist](RELEASE_CHECKLIST.md). Paid evaluations remain explicit, outside builds.

## Explicit content edition and lightweight sidebar

Multi-chapter content adjustment plans one owner for every whole Markdown topic before bounded chapter rewrites. The planner cannot certify adoption. Prose, claims and chapter understanding update together; the overview projects the same facts. Personal maintenance is protected, failures retain originals, and coverage markers do not prove semantic completeness. The operation remains an explicit BYOK action.

The sidebar retains local search, questions and project linking. Its separate project-context tab is retired; use workbench project export. Historical collections remain stored. Search follows stored originals without synchronizing or generating knowledge.

Submitted sidebar questions use BYOK by default, without intent-word gating. Typing and entirely quoted exact searches remain local. Each submission allows one interpretation call and one sourced-answer call, with one attempt each and existing caching/usage records. Up to three query phrases retain the selected scope. Up to eight excerpts bring relevant answers forward for question hits and adapt to the actual input budget. The answer has at most six paragraphs/1200 characters, each citing selected sources; at most five selected sources include literal quotes. Interpretation limits are 4000 input/400 output tokens; answering limits are 16000 input/3200 output tokens. The preceding question/answer resolves references but is not evidence. The UI retains four prior completed turns and clears them on scope changes. Missing AI configuration and failures are explicit and retain keyword results. Source changes prevent stale publication. Retrieval samples are not a complete archive review; this does not generate Wiki or modify originals.

Directory responses contain child support lists without generated keys or a second assignment map. Each material belongs to one parent; multiple child questions in that parent may share support. Parent lists are locally deduplicated unions and writing passages are sent once. Coverage, cross-parent conflicts and foreign references remain strictly validated. Legacy spelling normalizes only when explicit and unambiguous. Retries reuse completed reading batches.

Targeted v13 recovery locks uncontested ownership and supplies explicit slot IDs, their exact count and fixed destinations, up to sixteen slots per request. Valid partial mappings are retained and only unresolved IDs continue. Incomplete positional arrays, invented targets and cancellation never produce a guessed result. The winning parent retains its shared child references. Dedicated errors and safe JSON/CSV metadata distinguish repair failures from the original directory error. Only directory cache identity changes; completed source-reading identity stays unchanged.

Directory wire v13 normalizes empty obsolete maps and surrounding metadata whitespace while retaining exact source IDs. Only identical titles and scopes coalesce; signs, versions and distinct conditions remain separate. Inputs are snapshotted, duplicate appends and completion are idempotent, and personal or changed identities fail before model calls. Metadata correction remains one per window; ownership continuation shares that logical window's four-call/24,000-output allowance, including truncation splits. All local windows together have twelve repairs/24,000 output tokens; global reconciliation has a separate four-repair/24,000-output pool, also constrained by global routing limits. Reservations are synchronous; validated metadata and ownership cache hits refund repair allowance. Directory and reading cache identities remain unchanged. Global routing retains four rounds/seven requests and 24,000 output tokens. Chapter merging first sends one compact merge-plan request: the model returns only which chapters join and their new title and question, materials and subtopics combine locally, and a merge taking over 35% of the materials is refused; the routing rounds run only when the plan is invalid or leaves more than 20 chapters. One stalled response gets explicit feedback before repeated non-progress stops. Truncation recovery and the half-split re-plan after a correction returns the identical reply share an eight-call/30,000-token allowance. Caches preserve reading. External failures and unresolved ownership still stop without publishing incomplete knowledge.

Missing or foreign writing ownership and owner/citation mismatches enter bounded writing recovery after metadata repair fails. Recovery prefers complete support grouped by chapter and explicitly requests the current ownerId and matching citations. Successful child checkpoints retain their existing identity and are reused on continuation. Ambiguous citations still fail validation; titles and positions never determine ownership. Existing depth, request and output allowances remain unchanged. The error card separates completed reading from writing steps, including split repairs. Its primary notice follows the current UI language; original errors and original batch positions stay in diagnostics. A stage percentage does not guarantee overall completion.

Debugging benchmarks classify failures as local construction, model output, provider or network issues. Local pre-send stops are zero-cost records excluded from sent requests; unclassifiable older records remain unknown. Settings → Usage history → Developer tests exports the latest run CSV and compares before/after CSV files locally. `npm run benchmark:organization -- --sample redacted.json --before baseline.csv --after candidate.csv` analyzes existing records and sample fingerprints without model calls. Keep source scope, models and cache conditions equal; review quality separately.

Claim metadata recovery: when Wiki writing fails on quote/citation fields, retain the article and attempt one field-only repair using affected claims and their selected support. Article prose, claim text and chapter ownership cannot change. At most eight claims are repaired with an output ceiling up to 2,400 tokens, charged to existing batch/stage recovery limits. Quotes must match cited support literally; existing valid quotes and citation sets remain fixed. Missing citations require unique literal support. Claim-count overflow, missing claim text and unknown evidence keep source-backed recovery. Interrupted repairs retain the draft; fallback preserves learned split reuse. CSV/request diagnostics export safe field paths and reasons, never article prose. Normal reading/writing requests and legacy checkpoint keys remain compatible.

## Directory identity recovery and replay

New directory responses return an ordered `routes` array of chapter/subtopic indices. The application attaches its material IDs, derives parent inventories and validates the complete roster. Existing validated leaf inventories and checkpoints remain readable. A wrong route count cannot shift material positions; invalid destinations leave only their corresponding materials unresolved.

Foreign references in legacy responses are quarantined before rechecking the full real-material roster. Complete coverage with valid editorial metadata needs no extra model request. Missing materials receive targeted destination choices; ambiguous ownership is restricted to its declared candidates. Valid subjects, confirmed assignments and original evidence are retained. Scope contradictions, parent/child mismatches and invalid metadata still require bounded correction.

Each organizing unit has a primary chapter, with shared child support allowed. Separate units may cite the same original discussion across chapters. Identity validation does not establish that mixed-topic decomposition or semantic organization is good; real conversations still need review.

Progress exposes completed/reused windows, confirmed/pending assignments and quarantined references. Schema corrections, ownership recovery and duplicate-name repairs all carry recovery metadata. Diagnostics export counts and paths, never response prose. Directory timing starts at its first window, including overlap with reading; overlapping phase times are not additive. Model namespaces remain separate; switching back restores that model’s checkpoints.

`wiki-identity-replay.test.ts` reconstructs the screenshot/CSV failure signature (zero missing/duplicate/mismatched IDs plus one unknown reference), and tests repeated failures, valid-result preservation and model switching. Ordered routing also covers 554 materials. Raw model responses were absent from the export: reconstructed and mixed-topic fixtures are not live-model quality evaluations.
