# ChatAtlas architecture

[简体中文](../../ARCHITECTURE.md) · **English**


File import accepts official exports from ChatGPT, Claude, Gemini (Google Takeout JSON) and DeepSeek, plus Markdown/JSON transcripts from other AIs. Beta website adapters for Claude, Gemini, DeepSeek, Doubao, Kimi and Qianwen (including Qwen international) run automatically after browser website permission, with pause/resume controls. They support the native sidebar, local search, project association, loaded-message sync, source location and composer insertion. Website history import reads loaded titles and saves loaded bodies one at a time; it saves currently loaded messages, not guaranteed full history. ChatGPT retains its dedicated history inventory and body sync. The new adapters still need signed-in live-site acceptance; BYOK model providers are independent of conversation-source support.

## Runtime and storage

The Manifest V3 Chrome extension has two HTML entry points: `atlas.html` (workbench) and `sidecar.html` (native sidebar and compatible embedded surface). `src/background/` manages extension actions, permissions, sync and validated host operations. `src/content/` adapts supported AI websites. Fixed host permissions cover ChatGPT and the six website adapters; custom API endpoints still use optional permissions.

`src/storage/` uses IndexedDB for conversations, source versions, projects, notes, favorites, usage and reusable AI results. Existing database names, store keys, `atlas-*` identifiers, message protocols and backup schemas retain their previous identities for compatibility. ChatAtlas is the user-facing product name. Renaming the UI does not migrate user data or invalidate existing model caches.

## Source to knowledge

`src/sync/` imports ChatGPT exports and webpage history. Source versions preserve historical message bodies; source scope and content signatures bind interpretations to the material actually selected. `src/ai/focus-coverage.ts` performs budgeted reading, directory planning and writing, reusing valid requests and checkpoints. Complete candidate windows can overlap later source reading within one shared provider allowance. Global planning assigns parent scopes and restores local child topics and source ownership; dependent convergence rounds stay ordered.

Final Wiki output is checked for valid sources, explicit chapter ownership and subtopic coverage. Source-bearing schema recovery is local, bounded by depth and request count, and retains successful batches. Interrupted final writing has one local retry; this is not an unlimited retry of the original conversation. Read [AI_WORKFLOWS.md](AI_WORKFLOWS.md) for limits.

Generated prose, raw messages and personal edits remain distinct. Validation of IDs or quotes is not proof of semantic truth, adoption or implementation. Saving a project never upgrades a historical assistant proposal to a user decision.

Language validation exposes safe field paths and allows short technical labels. BYOK repair sends only invalid prose fields and applies a bounded translation patch to the locally retained response, preserving literal code/quotes and revalidating sources and ownership. Directory navigation includes compact fact subjects; writing keeps the complete detail inventory. Writing output ceilings scale with assigned subtopics. Editorial depth/result-table hints never trigger automatic paid regeneration or upgrade factual status.

## Saved documents and compatibility modules

`FocusWorkspace` and the example share `DocumentOverview`; they no longer mount independent Q&A, project-state hooks, matters or evolution components. New project documents are written from the knowledge-unit ledger by default (`wiki-ledger-document.ts` turns its draft into sections, evidence and claims) and keep the ledger; updates reuse unchanged batches, organize again and rewrite only changed chapters, keeping chapters the user edited and offering the new version as a suggestion. The earlier pipeline stays behind a developer fallback. `generateFocusUpdate` returns the document preview after merging prose, organizing chapters and checking source freshness; it no longer appends `enrichProjectState`. Legacy types, storage and local export remain. Old Q&A links open the document; continued organization requests open an editable revision preview. The following context and matters descriptions document compatibility code, not current workspace entries.

`src/context/saved-project.ts` selects saved overview, whole Wiki chapters and relevant records. Task matching, ordering, deduplication and budget selection are local. Explicit chapter selection preserves complete content and reports over-budget status. Raw messages are used for provenance/version checks; the default pack is not rebuilt from all historical proposals. The legacy context builder remains available for existing callers.

`src/shared/project-snapshot.ts` projects a compact overview from saved Wiki claims, with a conservative unreviewed-paragraph fallback for legacy analyses. It creates no new model requests or fact store and respects maintained descriptions. Context export carries stable message identities, deduplicates conversation identity/link metadata and reversibly factors repeated conversation prefixes out of displayed message IDs. Structured sources keep complete IDs.

`project-knowledge-facts.ts` and `project-knowledge-view.ts` share the saved facts across overview, prose and matters. The overview uses natural paragraphs. Supplement, narrow, replace, coexist and conflict relationships require original evidence, scope and chronology; adoption and delivery remain separate. Bound alternative prose formulations retain detail and qualification. Personal edits take priority.

`project-matter-assessment.ts` validates optional question/decision lifecycle metadata against original user statements, chronology and selected scope. Later answers have separate proof from the original question. The existing independent verifier reviews both bounded windows; uncertainty prevents closure. `project-work-queue.ts` separates unresolved matters from ordinary records; manual edits, reopening and historical states remain local maintenance. Incremental analysis retains prior questions and valid reading checkpoints instead of restarting the archive.

`knowledge-article-presentation.ts` projects generated Markdown for reading/export only: private reference columns, recognized uniform or mixed metadata status columns (qualifications move into prose) and narrowly recognized generated code/diagrams are simplified while preserving their qualification. Original excerpts, business states, executable code and personal edits are protected. Titles use subject planning and conservative compatibility aliases, never global conjunction stripping.

`src/context/composer.ts` is a separate optional BYOK operation. It receives only the reviewed pack and current task, applies a bounded single-request policy and reuses the existing `AtlasAI` cache and usage pipeline. Its request identity includes pack, task, style, locale, prompt version and model configuration. It never reads all conversations or writes Wiki. Input budget, structured body, output size, code fences and reference-number checks guard basic integrity; they do not establish factual completeness.

`ProjectContextComposer` previews candidates separately. Adoption is explicit; cancellation, late results and source changes do not overwrite the original draft. `ProjectContextDialog` keeps freshness checks before output, protects edited previews and exports the exact reviewed text. A refined draft is treated as an edited derivative; portable JSON does not misrepresent the original structured claims as the AI rewrite.

Project context uses one purpose preset instead of a second length control. Settings sit beside the preview; local changes reuse the open knowledge snapshot, coalesce rapid choices and memoize Markdown. Explicit refresh rereads saved knowledge; every output retains its independent freshness check.

The toolbar Export action uses `src/export/project-document.ts` for the saved overview, selected Wiki chapters and optional source excerpts. Markdown is the default; text, JSON and printable standalone HTML remain available. Saved matters/evolution appear only in a collapsed legacy selection. Private notes and unselected sources are excluded.

Legacy compatibility only, without active workspace generation or navigation: matters separate open work, ordinary records and handled items, grouped by explicit user placement, Wiki links or unambiguous evidence overlap. Large groups are folded and paginated. Search/type filters and bulk placement/closure preserve original records and conclusions. Bulk undo is disabled after another maintenance change. Candidate review defaults to actionable work and follow-up conclusions; ordinary records remain optional and similarity never triggers an automatic merge.

Generated directories have at most seven main chapters; every child and source assignment is retained. Preview omits project matters, enlarges chapter numbers and offers right-edge tick navigation for the chapters actually rendered, including changes-only mode.

## Interface responsibilities

Wiki reading uses a right-side tick navigator for the chapter’s main sections, replacing the page-contents dropdown. Hover/focus reveals titles; scrolling and keyboard navigation track the same section. The navigator is hidden during editing.

- Sidecar: explicit submissions use a BYOK discussion assistant without an intent-word whitelist. Typing and entirely quoted exact searches stay local. It expands queries within the selected scope, reads retrieved answers, then returns up to six short cited paragraphs and five literal source matches. Answers precede compact conversation cards; complete questions, replies and location actions expand on demand. The composer stays separate from the scrolling results. Up to four prior completed turns remain collapsed; the preceding question/answer resolves follow-ups but is never evidence. Scope changes clear this context. Missing configuration and failures visibly retain keyword results. Cancellation and source edits prevent stale publication. Project context and existing saved snapshots retain their separate responsibilities.
- Workbench: user intent, confirmed sources, generation and recoverable previews.
- Document overview: compact saved description, chapter reading order and sources.
- Wiki / Reader: long-term knowledge and continuous original discussion with precise source navigation.
- Home source list: the one conversation list. Sync and import, filter by AI and sync state, search titles and text, read originals, see each conversation's projects and add a selection to a project or start one. Leaving the Reader returns here.
- The main flow is select conversations → organize a document → review and edit → update on demand → export. A single conversation or multiple conversations across platforms can supply the material. Project navigation contains only the document overview, Wiki chapters and sources. Independent project Q&A, matters and evolution workspaces are retired. Ordinary document updates no longer append project-state, architecture or matters analysis; chapter ownership, source checks, update previews and personal-edit protection remain. Historical data is retained: saved matters and evolution can be selected under Previously saved records in export; old Q&A threads remain in local storage and backups without regeneration.

## Repository boundaries

Native navigation prioritizes actual user-message IDs, including IDs inside turn wrappers. Known ID anchors relate saved order to the native virtualized window; raw turn indices and saved indices are not interchangeable. Partial capture retains known messages' saved order. Recovery is bounded and interrupted by manual input, a new request or navigation. Other branches and missing material may remain unavailable; fixtures do not certify live compatibility.

Developer tests provide quick local regression, read-only saved-project checks and a folded searchable manual plan. They retain old records, make no model calls and do not certify live-model output.

The public build needs no backend. `src/shared/atlas/` contains synchronized frontend contract copies; authoritative backend sources live in a separate maintainer repository. Frontend work must not reconstruct deployment sources from local historical directories. Legacy hosted adapters are retained for compatibility tests, while the public runtime disables hosted-service configuration.

Development outputs, historical notes, private examples and diagnostics stay outside the explicit public source manifest. `scripts/public-source.mjs` defines and checks that manifest; the same list drives release packaging. CI runs lint, types, tests, production build, Worker import and public-file checks.

Explicit multi-chapter content adjustment first plans ownership across complete Markdown topic blocks. Every topic must be assigned once; writers receive whole assigned material and bound originals, returning prose, claims and understanding together. Personal content and maintained chapter boundaries remain protected. Topic coverage and literal-quote checks do not certify semantic completeness. Revisions publish only as a complete candidate; the overview projects at most three paragraphs from the same claims. Oversize inputs fail visibly without truncating originals or starting an automatic paid retry loop.

Directory wire v13 separates chapter ownership from child support. Each writing unit belongs to one parent, while different questions in that parent may share support. Parent inventories are locally deduplicated unions; each writing passage is sent once. Cross-parent conflicts, unknown references, omissions and parent/child disagreement still require resolution. Legacy labels normalize only when unambiguous. Source-reading cache identity remains unchanged. Direct reorganization of existing prose retains its strict subtopic boundaries.

Targeted recovery uses explicit slot IDs, an exact slot count and fixed destinations, with at most sixteen slots per request. Valid partial mappings are retained; only unresolved IDs continue. Incomplete positional arrays are never guessed. Resolving a cross-parent conflict retains every original child reference inside the chosen parent. Continuations share a four-call/24,000-output allowance with metadata correction inside each logical window. Local windows and final reconciliation have separate bounded pools; global repairs also count against global routing ceilings. Dedicated repair errors expose safe expected/received counts through the UI and JSON/CSV diagnostics instead of rethrowing the original directory error.

Directory planning snapshots inputs, deduplicates identical notifications and finishes once. Changed identities and personal text fail before model calls. Empty legacy maps and surrounding metadata whitespace normalize locally; source IDs remain exact. Coalescing requires identical title and scope, preserving signed conditions, versions and distinct questions. Each failed window gets at most one metadata correction; ownership continuations share that logical window's four-call/24,000-output allowance, including truncation splits. Local repairs total at most twelve calls/24,000 output tokens; final reconciliation has a separate four-repair/24,000-output pool, also constrained by global routing limits. Reservations are synchronous; validated metadata and ownership cache hits refund repair allowance without changing cache identities. Global reduction retains four rounds/seven requests and 24,000 output tokens. Shared-support connected components stay together during writing recovery, avoiding duplicated passages. One stalled global response gets explicit feedback; repeated non-progress stops. Non-finite concurrency limits fall back to one worker. These ceilings are request allowances, not measured charges.

## Multi-platform website adapters

`shared/web-capture.ts` owns site contracts and an explicit pause key. `background/web-capture.ts` checks permissions, registers a bundled dynamic reader and validates sender/conversation identity. `multi-ai-content.ts` reads only loaded messages through conservative DOM selectors. Shared `PageCapture` debounces and serializes writes, skips unchanged snapshots and discards pending reads after disable. Capture never invokes a model. Partial windows merge using stable IDs and known neighboring messages while retaining earlier messages. Fallback identities do not guarantee perfect reconciliation of branches or identical repeated questions. These adapters remain Beta without signed-in live-site acceptance. Registered adapters cover Claude, Gemini, DeepSeek, Doubao, Kimi (current and legacy domains), Qianwen China and Qwen international. Regional Qwen identities are separate. The settings view can inspect open tabs and explicitly save a selected conversation’s loaded messages; it checks identity again before capture and persistence. These sites use loaded website history links and bounded sequential imports through extension-created inactive tabs, not private history APIs. Imports stop on permission loss, preserve successful saves and leave a tab open if the user activates it. A stable rendered window never proves full-history completeness. The Reader labels DOM records as potentially incomplete. Selector fixtures cover role boundaries, nested Markdown, tool/thinking exclusions, streaming, changed conversations, connection errors and revoked permission.

`AIPlatformFilter` serves the home source list. AI, sync and search filters intersect; selection survives category changes. ChatGPT bulk hydration never receives another platform ID.

Settings use separate AI connection, Capture & data, and Usage history views. Common connection and model controls follow setup order, optional parameters stay collapsed, and AI test/save actions remain fixed below the scrolling form. Usage no longer widens the panel. Generation failures, connection feedback and capture errors resolve their primary text in the current UI language; diagnostics preserve original details.
