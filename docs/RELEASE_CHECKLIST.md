# ChatAtlas GitHub 发布清单

**简体中文** · [English](en/RELEASE_CHECKLIST.md)

目标：0.1.1 Early Preview 的公开前端源码和可加载 Chrome 扩展。无需共享后端。本清单本身不表示已完成线上验收。

发布范围区分多平台文件导入、ChatGPT 批量历史同步与原生侧栏、Claude/Gemini/DeepSeek 可选网页采集试用。中文和英文说明应一致；手动上下文复用和 BYOK 服务商选择不算网页适配。

## 可复现构建

```bash
npm ci
npm run check
npm run check:public
npm audit --registry=https://registry.npmjs.org
pwsh -File scripts/package-demo.ps1
```

打包前需通过完整检查；打包后从生成的源码 ZIP 解压到全新目录，再运行 `npm ci`、`npm run check` 和 `npm run check:public`，确认包含 `sidecar.html`、配置、脚本、测试夹具、当前文档与 LICENSE。扩展 ZIP 解压后应直接包含 `manifest.json`、`atlas.html` 与 `sidecar.html`，不含开发服务器加载器。

脚本使用显式公开文件清单，同时生成 `SOURCE_FILES.txt` 和 SHA256 校验文件；不自动推送、建 Release 或部署。`release-output/`、`.env`、本地诊断、历史私人例子与部署文件不进入源码包。公开检查还会在 Git 仓库中拒绝已跟踪但不在公开清单内的文件。

## 浏览器验收

使用新的浏览器配置和虚构材料：

- 加载扩展，新开 ChatGPT 页面，检查图标、页面入口、原生侧栏和快捷键；关闭／切换对话不自动重新打开或发送。
- ZIP/JSON 导入、网页同步、暂停继续和空／旧材料覆盖保护。
- 默认关键词查找不调用模型；打开完整原文、引用返回和阅读位置正常。
- 已有项目离线可读；章节、个人编辑、收藏、备份恢复正常。
- 本地项目上下文不需 API；显式章节完整，编辑稿受保护，复制／导出一致。
- 可选精炼：开始前无请求；失败／取消保留原稿，候选需主动采用，可还原；来源变化阻止过期候选。输入草稿不被插入覆盖。
- 问答／演进实验标识、架构生成开关、高级语义设置符合当前范围。
- 浅色、深色和窄屏没有整页溢出；长代码可局部滚动。
- 空状态只有一个主要操作；无正文先获取，有问答再标重点；隐藏重点可从菜单恢复。上下文与收藏同页，任务与编辑稿在展开收藏、查看原文和返回时保留。
- 长对话定位检查导出导入后、局部采集后、页面中段和分支变化场景；不能仅凭调用滚动 API 就宣称定位成功。
- 两套维护文档互相可切换、链接有效，并实际包含在公开源码清单中。

本地浏览器夹具不等于当前 ChatGPT 线上页面已验证。

## 真实模型验收（需要维护者主动执行）

使用自编或同意发给该服务商的脱敏资料，记录服务商、准确模型 ID、输入输出 Token、总耗时、实际费用或费用未知、失败和恢复次数。

| 场景 | 检查 |
| --- | --- |
| 短／长对话首次整理 | 最终选择、后续纠正、重要条件与来源完整性 |
| 同材料再整理或中断后继续 | 成功批次复用，无重复整库初读或无进展循环 |
| 来源追加、修改与删除 | 仅影响相应知识，个人编辑保留，不伪造解决状态 |
| 快速提问精炼 | 确实更短，否定条件与未采纳建议不丢失，费用可解释 |
| 新 AI 接手续聊 | 只给 Context Pack，能识别背景／当前任务／未知事实；用固定问题人工评分 |

自动化使用模拟服务商，不能替代以上证据；没有实测数据就不要宣称固定速度、压缩率或全模型稳定性。

## GitHub 操作

1. 仅将公开源码清单中的内容提交到仓库；MIT 与第三方通知一并保留。不要直接上传整个本机工作目录。
2. 首次推送前运行 `npm run check:public`，检查 staging；`.gitignore` 不能移除已经跟踪的文件。
3. 等待 GitHub Actions 实际通过后，为匹配源码创建对应版本 Release。
4. 附 `ChatAtlas-extension-v0.1.1.zip`、可选源码 ZIP、SHA256 和本次验证说明。
5. 明确标注 Early Preview、BYOK、数据存本机以及已知限制。

上传、推送、线上工作流执行和真实付费评测不包含在本地准备完成的结论中。

## 可选网页采集试用验收

- 逐站确认授权前不采集、开启后可保存已加载问答、关闭后停止写入；不增加模型请求。
- 在当前登录页面核对角色、代码与表格、流式结束、长对话局部加载、切换对话与重复写入。DOM 夹具与生产构建测试不能代替真实账号页面兼容性验收。
- 首页来源列表核对 AI 分类、状态与搜索（标题与正文）组合、保留已选、阅读原文、加入项目、窄屏滚动。
- 当前新增适配尚未通过登录后的线上页面人工验收，应保留试用标记。Gemini Takeout 的时间分组与网页原生对话 ID 不同，不承诺自动合并。

## 性能基准

在设置 → 使用记录 → 开发者测试中，先运行本地回归，再用独立测试项目整理固定脱敏样本。每轮结束后点击「导出最近任务 CSV」，保存为基线和优化后两份文件；同页选择两份 CSV 即可查看请求、各阶段请求、Token、缓存读取、失败来源及耗时差异，并导出对比 JSON。其他任务可从「任务诊断」导出 CSV。

离线复现（可重复传入 `--sample`）：

```sh
npm run benchmark:organization -- --sample redacted-export.json --before baseline.csv --after candidate.csv --json comparison.json
```

不传 `--after` 时输出单份基线。脚本只读取本地文件，对样本计算 SHA-256 指纹，不导入或修改项目，不调用模型。脱敏需开发者自行完成。缺失时间/缓存指标显示未知；首次可读采用已测任务的中位数，累计耗时按任务求和，并发请求耗时不直接相加。旧 CSV 没有失败来源时归为 unknown。比较前核对样本指纹、消息范围、模型、任务数、缓存冷热与任务完成状态；手工抽查章节、引用和原始条件，性能差异不能证明质量未下降。

手工构造的示例可运行（仅用于验证工具，不是真实模型性能数据）：

```sh
npm run benchmark:organization -- --sample scripts/fixtures/organization-benchmark/sample.json --before scripts/fixtures/organization-benchmark/before.csv --after scripts/fixtures/organization-benchmark/after.csv
```
