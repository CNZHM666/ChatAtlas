## 用户交互流程

用户通过打开插件直接进入计时首页，无需注册或引导即可开始专注。默认采用50分钟专注与10分钟休息的循环机制，所有阶段转换均由用户手动触发，暂停时间不计入学习时长，提前结束仅计入总时长而不算作完成一个番茄钟。

### 启动与初始化

安装插件后打开即进入计时首页，界面默认展示初始状态，无需注册、登录或引导问卷。底部区域展示今日统计数据，初始值为0。

### 专注阶段操作

- **开始计时**：点击“开始专注”后系统记录状态并立即开始倒计时，填写任务名称为可选步骤，不应成为必要阻碍。
- **暂停与重置**：暂停时间不计入实际学习时长；重置或提前结束时需提示确认，且未完成完整时长的记录不应直接算作完成一个番茄钟。
- **提前结束处理**：提前结束的专注计入今日专注时长但不计入番茄钟数，以平衡用户体验与数据准确性。
- **阶段衔接**：完成专注或休息后仅提醒用户，由用户手动开始下一阶段，避免自动计入未实际完成的学习时间。

### 休息与循环机制

当前推荐不自动开启休息倒计时，而是发送通知并等待用户主动点击“开始休息”，以避免打断用户正在进行的任务。

## 技术实现架构

底层代码采用 Chrome Manifest V3、TypeScript 和 Vite，界面层使用原生 TypeScript 配合轻量 DOM 操作。计时逻辑基于结束时间戳与 chrome.alarms 实现，不依赖 Service Worker 内存中的 setInterval，确保在弹窗关闭或浏览器重启后能恢复状态。

### 技术栈与权限

项目技术栈采用 Chrome Manifest V3、TypeScript、HTML/CSS 和 Vite。**界面层不使用 React**，而是采用原生 TypeScript 配合轻量 DOM 操作，以减小包体积和构建复杂度。

| 技术 | 用途 |
|---|---|
| TypeScript | 核心业务逻辑 |
| HTML + CSS | 弹窗界面 |
| Vite | 项目构建 |
| Chrome Manifest V3 | Chrome 扩展规范 |
| Chrome Storage API | 保存设置、计时状态和学习记录 |
| Chrome Alarms API | 安排后台计时结束事件 |
| Chrome Notifications API | 系统提醒 |

- **权限申请**：第一版仅申请 storage、alarms、notifications 权限，不访问用户浏览内容，符合最小化原则。
- **存储封装**：读写封装在独立模块（如 storage.ts）中，对外暴露 saveSession、getTodaySummary 等函数。
- **事件注册**：Service Worker 中所有事件监听器必须在顶层同步注册。
- **状态管理**：不依赖全局变量保存状态，所有状态均从 chrome.storage.local 读取。

### 计时核心引擎

**计时机制基于结束时间戳计算剩余时间**，并利用 chrome.alarms 安排结束事件。由于 Popup 关闭和 Service Worker 终止会导致 setInterval 失效，必须避免依赖 Service Worker 内存中的 setInterval，而非依靠持续运行的 setInterval；Service Worker 不要求一直运行，确保关闭弹窗或重启浏览器后能恢复计时状态。

*讨论中的原文代码 · AI建议，未确认*

```text

结束时间：10:25:00

将结束时间保存到本地

用户关闭弹窗

用户在 10:12:30 重新打开弹窗

剩余时间 = 结束时间 - 当前时间
         = 12分30秒
```

- **角标更新**：允许系统延迟更新角标，通过 chrome.action.setBadgeBackgroundColor() 设置颜色。
- **Alarm 粒度**：Chrome 120 起 alarm 最小周期为 30 秒，本产品按分钟更新角标，该粒度满足需求。
- **状态恢复**：关闭 Popup 不会终止计时，再次打开时根据本地持久化的状态和时间戳恢复正确的剩余时间。
- **超时处理**：从本地恢复上次状态，若已过结束时间则标记为已完成或待处理，不自动补算多轮。
- **休眠恢复**：电脑休眠恢复后重新计算状态防止负数或重复记录；通知被禁用时计时仍正常运行。
- **触发重算**：Service Worker 启动或 Alarm 触发时，需读取存储中的会话状态重新计算实际状态，而非假设刚结束。
- **幂等保护**：通过 sessionId 和存储状态标记确保同一次专注只记录一次，防止重复写入。

### 数据模型存储

V0.1 采用 chrome.storage.local 作为唯一存储层，使用分片键结构（session:<id> + sessionIndex）而非单一数组，**以优化读写性能并避免写入冲突**。存储方案保持 A1（分片键）与 A2（单键数组）两案并存，未最终指定前不自行选定。无论选择哪种方案，均不使用 chrome.storage.sync，不存储累加计数器，以原始记录驱动今日汇总。
